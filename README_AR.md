# IRAQI TIK — لوحة الإدارة + Cloudflare Worker

هذه حزمة نشر يدوي. لم تُنشر تلقائيًا على Cloudflare أو GitHub Pages.
الواجهة برغندي زجاجية، بشعار التطبيق الأصلي، ومتجاوبة للجوال والكمبيوتر.

## ما الموجود؟
- docs/: ملفات الموقع الثابت الجاهزة للنشر على GitHub Pages. لا ترفع مجلد worker ضمن ملفات الموقع.
- worker/worker.mjs: كود Cloudflare Worker، يمكن نسخه في محرر Cloudflare مباشرة.
- worker/wrangler.toml: إعداد جاهز لمن يفضل النشر بالأوامر.
- worker/test.mjs: اختبارات محلية بمحاكاة GitHub وR2.

## الربط بالتطبيق
المستودع: IRAQIEDITOR/iraqi-exzotiktok
ملف التحكم: iraqi-tik.json على فرع main.
التطبيق المرفق يقرأ هذا الملف نفسه. لا تحتاج وضع رابط Worker داخل تطبيق المستخدمين؛ Worker للإدارة فقط.
رفع المثبّت في اللوحة ينشئ GitHub Release ثم يحدّث هذا الملف بعد نجاح الرفع والتحقق.
لا تغير version.json القديم الخاص بـEXZO.

## 1 — إنشاء مفتاح GitHub
من GitHub Settings > Developer settings > Personal access tokens > Fine-grained tokens:
- اختر حساب IRAQIEDITOR والمستودع iraqi-exzotiktok فقط.
- Repository permissions: Contents = Read and write.
- اختر مدة صلاحية مناسبة واحتفظ بالمفتاح في مدير كلمات مرور.
ستضعه في Cloudflare Secret باسم GITHUB_TOKEN؛ لا تضعه في الموقع أو ترسله في الدردشة.

##  — إعداد Cloudflare يدويًا
1. افتح R2 وأنشئ bucket خاصًا باسم iraqi-tik-update-staging. لا تفعّل الوصول العام.
   R2 مطلوب لتجميع الملفات الكبيرة على أجزاء. قد يطلب Cloudflare تفعيل R2 وبيانات فوترة؛ راجع شروط وتكلفة حسابك بنفسك قبل الموافقة.
2. أنشئ Worker باسم iraqi-tik-admin من Workers & Pages، وافتح Edit code.
3. استبدل كود البداية بمحتوى worker/worker.mjs ثم Deploy.
4. أضف R2 bucket binding: الاسم UPLOADS، واختر الـbucket أعلاه.
5. أضف Text variable: ALLOWED_ORIGIN = https://iraqieditor.github.io (بدون مسار أو شرطة أخيرة).
6. أضف Secret: GITHUB_TOKEN = التوكن الذي أنشأته.
7. أضف Secret: ADMIN_KEY = مفتاح إدارة عشوائي قوي بطول 32 حرفًا على الأقل؛ يفضل 64 حرفًا عشوائيًا من مدير كلمات مرور.
   هذا هو مفتاح دخول اللوحة، وليس كلمة سر Cloudflare. لا تنشره في GitHub.
8. احفظ وانشر الإعدادات. انسخ رابط Worker الأساسي الذي ينتهي بـworkers.dev.
9. في إعدادات lifecycle الخاصة بالـbucket، اضبط حذف الملفات المؤقتة بعد يومين، وإلغاء multipart uploads غير المكتملة بعد يوم.
   النسخ المنشورة بنجاح تُحذف من R2 آليًا؛ lifecycle ينظف المحاولات المنقطعة.

## 3 — نشر الموقع على GitHub Pages
ملفات الموقع موجودة بالفعل في مجلد docs داخل المستودع:
  docs/index.html, docs/style.css, docs/app.js, docs/logo.png, docs/icon.png, docs/.nojekyll
اترك iraqi-tik.json في جذر المستودع، لا تنقله.
من Settings > Pages اختر Deploy from a branch ثم main والمجلد /docs.
الرابط المتوقع بعد نجاح النشر: https://iraqieditor.github.io/iraqi-exzotiktok/
افتح الموقع، أدخل رابط Worker ومفتاح ADMIN_KEY.
الرابط محفوظ محليًا لتسهيل الرجوع؛ المفتاح لا يُحفظ في localStorage أو sessionStorage.
لا يوجد اسم مستخدم أو كلمة سر افتراضية. الواجهة عامة، لكن كل عمليات API تتطلب مفتاح الإدارة.
للدومين المخصص: غيّر ALLOWED_ORIGIN؛ الواجهة الحالية تقبل Workers.dev كخادم فقط.

## 4 — تجهيز التطبيق ونشر أول نسخة
1. فك حزمة التطبيق كاملة. شغّل SETUP.bat ثم RUN.bat للاختبار.
2. شغّل BUILD_INSTALLER.bat لإنتاج dist/IRAQI_TIK_Setup.exe.
3. في اللوحة اختر هذا المثبّت ورقم 1.5.0، واكتب الملاحظات ثم نشر.
4. لأول مرة يمكن نشر نفس رقم 1.5.0 إذا ملف التحكم لم يحتوِ رابط تنزيل بعد.
5. للإصدارات التالية ارفع الرقم في update_client.py وinstaller/IRAQI_TIK.iss إلى نفس الرقم (مثل 1.5.1)، ثم ابنِ المثبت وارفعه.
   كتابة رقم جديد في اللوحة لا تغيّر رقم EXE الداخلي؛ عدم التطابق يؤدي إلى تكرار طلب التحديث.
6. تأكد أن الملف هو Setup.exe وليس EXE المحمول؛ النظام يشغّل المثبّت لتحديث النسخة.
7. رفع اللوحة لا يغيّر إيقاف/تشغيل التطبيق؛ يحافظ على الحالة الحالية.

## استخدام اللوحة
- زر حفظ حالة التطبيق ينشر enabled وmessage.
- تحديث رقم أعلى إلزامي للتطبيق؛ الفحص كل 60 ثانية تقريبًا مع احتمال تأخر الشبكة/CDN.
- المثبّت أقل من 2 GB، ويرفع على أجزاء 8 MiB. لا تغلق الصفحة أثناء الرفع والنقل النهائي.
- إذا انقطع رفع جزء اضغط نشر مرة أخرى بنفس الملف والإعدادات والصفحة المفتوحة؛ يكمل من آخر جزء نجح.
- إذا أُغلقت الصفحة تبدأ رفعًا جديدًا. تنظف lifecycle المحاولات القديمة.
- فشل مرحلة النقل/النشر لا يعلن نسخة ناقصة في ملف التحكم. قد يبقى Draft أو Release غير معلن؛ أعد المحاولة بنفس الإصدار والملف.
- لا تستبدل ملفًا مختلفًا بنفس رقم إصدار؛ استخدم رقمًا أعلى.
- يمكن إعادة تشغيل التطبيق عبر تفعيل الإتاحة ثم الحفظ.
- النسخ التي لم تتضمن نظام التحديث أصلًا لا تتأثر.

## أوامر اختيارية للنشر من الكمبيوتر
ثبّت Node.js ثم داخل worker:
  npm install
  npx wrangler login
  npx wrangler r2 bucket create iraqi-tik-update-staging
  npx wrangler secret put GITHUB_TOKEN
  npx wrangler secret put ADMIN_KEY
  npm run deploy
إذا أنشأت bucket مسبقًا تجاوز أمر إنشائه. أدخل الأسرار في الطرفية عندما يسألك Wrangler؛ لا تكتبها داخل الملفات.

بعد نسخ ملفات site إلى docs في نسخة المستودع المحلية:
  git add docs
  git commit -m "Add IRAQI TIK glass admin panel"
  git push origin main

## التحقق وحدوده
نجحت اختبارات محلية لرفض الطلبات غير المصرح بها، CORS، ترتيب الإصدارات، رفع متعدد الأجزاء، نشر الإصدار، حفظ بصمته، المحافظة على حالة الإيقاف، ورفض خفض الإصدار (GitHub وR2 محاكاة).
لم يتم تشغيل تكامل حي على حساب Cloudflare أو إجراء رفع EXE حقيقي؛ يحتاج إعداد أسرارك والنشر والاختبار على حسابك.
لم يتم بناء Windows EXE هنا. كل ملفات خوارزميات الفيديو الأصلية محفوظة دون تغيير.
لا توجد حماية تمنع مدير الجهاز نهائيًا من تعديل نسخته المحلية. مفتاح الإدارة يمنح التحكم بالمستودع المحدد عبر API؛ احتفظ به خاصًا ودوّره إذا انكشف.
